# テストについて

[English version](README.md)

このフォルダには、EnvGeo-Seawaterのための小さな`pytest`自動確認を置いています。

各テストは、自動化したチェックリスト項目です。たとえば、次を確認します。

- Pythonが共通ユーティリティをimportできるか
- 同梱データセットを読み込めるか
- 重要な数値列が読込み後も数値として扱えるか
- 値が広い物理範囲に収まるか
- `**`などのプレースホルダーを解析前に除去できるか
- 無効値を`NaN`へ変換しつつ元の値を確認可能に保てるか
- 折れ線を分ける必要がある箇所だけに`insert_gap_rows()`が空行を加えるか
- 安定版のStreamlitページが有効なPythonとしてコンパイルできるか
- 開発repositoryでは、公開対象外のローカル／開発ページも安定版の公開範囲を変えずにコンパイルできるか
- READMEの画像リンクが実在するファイルを指すか
- 公開用README・更新文書に内部の投稿状況を示す表現が含まれないか
- 安定版の公開面が、宣言した可視化ページだけを含むか

`envgeo_seawater_v130`ディレクトリから次を実行します。

```bash
python -m pytest -q
```

GitHub ActionsではPython 3.10と3.12で同じテストを実行し、wheelを作成して隔離環境へinstallしたwheelも確認します。CIと手動QAの詳しい範囲は`docs/testing.md`と`docs/testing_Japanese.md`を参照してください。

`pytest`は`.pytest_cache/`を、Pythonは`__pycache__/`を作成する場合があります。これらはローカル生成物であり、`.gitignore`で除外されています。

## テストの読み方

たとえば、次の行は、読込み後の表が空であってはならないことを意味します。

```python
assert not df.empty
```

条件が満たされない場合、pytestは失敗した確認項目を報告します。

テストは、主要な科学ワークフロー（読込み、前処理、絞り込み、図の準備、ユーザーデータの扱い）を守る安全網として、必要に応じて拡充します。
