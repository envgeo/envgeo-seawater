# T-S図の密度等値線 — 監査記録と実装方針

**状態:** 設計記録。Stage 1の透明化作業はv1.3.4で実装済みであり、Stage 2–3は将来の
科学的な開発作業として残る。
**記録日:** 2026-09-24  
**対象:** `pages/34_T-S_diagram.py` とT-S図が利用するデータ列。

## この記録を残す理由

T-S図は探索的な可視化である。密度等値線の定義や計算を変更すると科学量が変わり得るため、コードを変更する前に、現行動作、監査結果、段階的な移行案を記録する。

## 現行実装

現在のページは塩分・水温の格子を作り、次を評価している。

```python
sigma_theta = gsw.sigma0(Sg, Tg)
```

ここで`Sg`は`Salinity`列、`Tg`は`Temperature_degC`列から作られる。ページ、README、専用manualは、
この層を近似的な`σ0`参照等値線として示し、各試料ごとの密度ではないことを説明している。

この呼び出しはTEOS-10と整合していない。`gsw.sigma0`は基準圧0 dbarに対するポテンシャル密度異常（`σ0`）を計算する関数であり、Practical Salinity（`SP`）と現場水温（`t`）ではなく、Absolute Salinity（`SA`）とConservative Temperature（`CT`）を要求する。そのため、現行の等値線は試料ごとに計算された密度ではなく、近似的な参照線として扱う必要がある。

## 監査結果（2026-09-24）

`envgeo_utils.load_isotope_data()`が読み込む公開データ5表を、読み取り専用で確認した。温度・塩分が利用できる行では、既存の品質クリーニング規則を前提に、位置・水深に必要な列がそろっている。

| 読み込み元workbook | 利用可能な塩分 / 温度の行数 | 緯度・経度・水深 |
| --- | ---: | --- |
| `01_ECS_JAPAN_SEA_Kodam_et_al_2024.xlsx` | 2,222 / 2,221 | 全行で利用可能 |
| `11_AROUND_JAPAN_PUB_20260305.xlsx` | 419 / 416 | 全行で利用可能 |
| `71_GLOBA_NASA_20260226.xlsx` | 23,246 / 20,605 | 全行で利用可能 |
| `71_GLOBAL_Atwood_et_al_2026_v02.xlsx` | 16,098 / 13,871 | 全行で利用可能 |
| `72_GLOBAL_RECENT_REPORTS_20260302.xlsx` | 35 / 35 | 全行で利用可能 |

保守的な物理範囲で抽出した行について、現行の数値近似と点ごとのTEOS-10計算を比較すると、workbookごとの`σ0`差の中央値はおよそ+0.11〜+0.13 kg m^-3、グローバルデータでは絶対差の最大がおよそ0.43 kg m^-3だった。この比較はデータセット固有の科学的検証を置き換えるものではなく、改修優先度を判断する材料である。

ソースローダーは、現在定義された温度・塩分・水深の有効範囲外の値を`NaN`へ変換し、品質フラグを保持する。一方で、汎用列`Salinity`がすべてPSS-78のPractical Salinityであること、また各温度がITS-90の現場水温として明示的に記録されていることまでは保証しない。任意のユーザー表でTEOS-10計算を有効化するには、この来歴確認が別途必要である。

## 科学的な解釈

UI上で`σ0`と`σθ`を同義に扱わない。前者はTEOS-10 GSW関数における基準圧0 dbarのポテンシャル密度異常である。後者の表記は、厳密な定義・計算を実装し文書化した場合のみ使用する。

生のSP・現場水温を軸にした図には、位置と圧力から独立した一意の厳密TEOS-10等値線面は存在しない。SP/tからSA/CTへの変換には地理位置と圧力が入るからである。したがって、各試料のTEOS-10密度と、2次元図上の背景参照線は、別の概念として提示する。

## 完了した透明化作業（Stage 1）

v1.3.4では、現行の近似を透明化する非科学的な修正を完了した。

- UI、README、manualで`σθ`ではなく「Approximate σ0 reference contours」を使用する。
- 図中で、各試料の密度ではなく視覚的な参照ガイドであることを説明する。
- 等値線格子は表示軸範囲に従い、文書化したGSW入力範囲（温度−5〜45 °C、塩分0〜50）に制限する。
- 現行の動作はT-S用の焦点テストとページ／アップロードの広いテストで確認する。これらは点ごとの
  TEOS-10変換を数値検証するものではない。

## 将来の段階的作業

### Stage 2 — テスト可能なTEOS-10変換

- 確認済みSP、現場水温、水深、緯度、経度を受け取る、文書化された純粋関数を作る。
- `gsw.p_from_z(-depth_m, latitude_degN)`で圧力を計算し、
  `SA = gsw.SA_from_SP(SP, p, lon, lat)`、
  `CT = gsw.CT_from_t(SA, t, p)`を計算する。
- 変換の可否と理由を明示的に返し、不足する水深・座標を補完しない。
- GSW/TEOS-10の固定参照値、欠損値、不正値、品質フラグ保持をテストする。
- 来歴・表示方針を確認するまで、派生値を元データ列と区別し、表やダウンロードへ無言で混ぜない。

### Stage 3 — 明示的なTEOS-10可視化モード

- 条件を満たす行について、オプトインの**SA–CT（TEOS-10）**図を提供する。この座標系では`gsw.sigma0(SA, CT)`の等値線は明確な意味を持つ。
- 比較や不完全なアップロード用には、近似であることを明記した従来のSP–現場水温図を残す。
- ユーザーデータでTEOS-10モードを有効にする前に、塩分がPractical Salinity（PSS-78）であることを明示的に確認する。
- TEOS-10変換から除外された行数と理由を表示する。

## Stage 2またはStage 3を導入する前の受入条件

- 分野の確認者が、同梱する各データセットの対象列の意味を確認する。
- GSW依存関係・バージョンとTEOS-10引用をリリース文書へ記録する。
- 図が描けることだけでなく、数値の参照値を検証するテストを追加する。
- UI、manual、ダウンロード、引用で、ソース測定値と派生したTEOS-10量を区別する。
- 現行の近似層を残すか、SA–CTモードで補完／置換するかをrelease noteに明記する。
